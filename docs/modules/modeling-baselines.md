# Module 3: Text and Context Modeling Baselines

## Status

The first model ladder is implemented and trained on the reproducible seven-shard local sample. Chronological and user-disjoint local holdouts are both evaluated. The results are exploratory and sample-specific. Per-prediction linear contributions and CatBoost SHAP values are exposed in the local demo. A larger representative sample and explanation stability checks remain future work.

## Purpose and Scope

Compare a simple constant predictor with text-only, structured-context, and combined text/context regressors. The model predicts the supplied SMP popularity `label` using fields available at a planned publication time. It does not use images, user/profile snapshots, engagement counts, IDs, coordinates, or the unlabeled public test split.

The source papers motivate comparing modalities and feature groups, but the selected-shard data and local chronological split differ from the official challenge protocol. Do not compare these scores directly with the reported 2024 paper table.

## Input and Features

Input is `data/train-sample.parquet`, generated by [Cleaning and EDA](cleaning-and-eda.md), with revision and shard provenance in `data/train-sample-manifest.json`. The cache contains `Postdate`, `Category`, `Subcategory`, `Concept`, `Title`, `Alltags`, and `label`; it has no user or post IDs and no image paths.

- **Text:** title and tags joined into one field, TF-IDF unigram/bigram terms, `min_df=2`, up to 150,000 features, and Ridge regression (`alpha=2`).
- **Context:** category, subcategory, concept, and cyclic UTC hour, weekday, and month features, fitted with CatBoost (500 iterations, depth 8, learning rate 0.05).
- **Text + context:** the TF-IDF representation plus one-hot category/subcategory/concept and cyclic time features, fitted with Ridge (`alpha=2`).
- **Median:** the training-label median, as a non-learned reference.

The timestamp is parsed as Unix seconds. Invalid timestamps and missing, nonfinite, or negative labels are excluded before the split. No target is recomputed.

## Evaluation Protocol

Rows are ordered by `Postdate`; the final 20% by time is a local holdout and all earlier rows are training data. Equal timestamps at the cutoff go to the holdout. This future-time evaluation may share users across partitions. A separate user-disjoint group holdout is reported below. The sample itself is seven evenly spaced physical shards, not a random row sample; these limitations constrain generalization claims.

Report **SRC** (Spearman rank correlation) and **MAE** (challenge-aligned metrics), plus **RMSE** and **R²**. Training metrics diagnose fit; holdout metrics are the main result. The public HF test labels are withheld placeholders and are not scored.

## Completed Results

The run used 42,730 valid rows: 34,184 train and 8,546 chronological holdout, with cutoff `2016-01-11T08:05:51Z`.

| Model | Train SRC | Train MAE | Holdout SRC | Holdout MAE | Holdout RMSE | Holdout R² |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Median | n/a | 2.066 | n/a | 2.013 | 2.494 | -0.000 |
| TF-IDF + Ridge | 0.938 | 0.696 | 0.575 | 1.623 | 2.058 | 0.319 |
| Context CatBoost | 0.788 | 1.152 | 0.317 | 1.898 | 2.383 | 0.087 |
| Text + context Ridge | 0.941 | 0.642 | 0.578 | 1.642 | 2.066 | 0.314 |

The combined model improves holdout SRC slightly over text alone, but has slightly worse MAE, RMSE, and R². There is no evidence here that adding context improves overall score estimation. Large train-to-holdout gaps indicate overfitting, especially for sparse text features; no parameter tuning was performed on the holdout.

### Holdout error diagnostics

The training run saves actual-versus-predicted, residual histogram, and per-category MAE charts under `artifacts/diagnostics/`, and adds residual summaries/category metrics to `artifacts/baseline-metrics.json`.

| Model | Mean error (predicted - actual) | Median absolute error | 90th-percentile absolute error | Within 2 label units |
| --- | ---: | ---: | ---: | ---: |
| TF-IDF + Ridge | +0.543 | 1.373 | 3.432 | 68.4% |
| Context CatBoost | +0.131 | 1.640 | 3.910 | 59.1% |
| Text + context Ridge | +0.537 | 1.406 | 3.358 | 67.2% |

Positive mean error denotes average overprediction. Category metrics include groups with at least 50 holdout rows. In this sample, text + context has the lowest category MAE for Food (1.268 on 662 posts); all three models have their highest category MAE in Family (2.067 / 2.034 / 2.090 on 68 posts). Small category slices are less stable, and none of these sample patterns should be treated as full-dataset or causal findings.

The saved charts are `holdout-actual-vs-predicted.png`, `holdout-residuals.png`, and `holdout-mae-by-category.png`. The local UI renders all three through the allowlisted `/api/diagnostics/{filename}` route.

## User-Disjoint Evaluation

`viralscope.user_aware_eval` fetches only `Uid` from the exact seven shards listed in the sample manifest. It verifies the pinned revision and row alignment, uses IDs only as `GroupShuffleSplit` groups, and keeps ID values in memory. IDs are neither model features nor written to the cache, report, or repository. The fixed random seed is 42.

The user-disjoint result uses 33,680 train posts from 8,780 users and 9,050 holdout posts from 2,196 unseen users; measured user overlap is zero.

| Model | Chronological SRC | Chronological MAE | Unseen-user SRC | Unseen-user MAE |
| --- | ---: | ---: | ---: | ---: |
| TF-IDF + Ridge | 0.575 | 1.623 | 0.443 | 1.835 |
| Context CatBoost | 0.317 | 1.898 | 0.428 | 1.890 |
| Text + context Ridge | 0.578 | 1.642 | 0.548 | 1.775 |

The group holdout is randomly assigned by user and is not time-ordered. It complements, rather than replaces, the chronological evaluation. Text + context leads on the user-disjoint holdout; its performance is lower than on the chronological holdout, which is consistent with a harder unseen-user setting but does not isolate user effects from the different holdout composition. A future-time, unseen-user evaluation would require a combined split protocol.

The aggregate report is `artifacts/user-aware-metrics.json`; model files and plots are kept in `artifacts/models/user-aware/` and `artifacts/diagnostics/user-aware/`. The report contains user counts and overlap only, never raw IDs.

## Temporal Sensitivity

`viralscope.temporal_sensitivity` evaluates chronological tail holdouts of 15%, 20%, and 25% using the same sample and model settings. It writes one aggregate report to `artifacts/temporal-sensitivity.json`; temporary models and plots are deleted after each run.

| Holdout tail | Rows | Cutoff (UTC) | TF-IDF SRC / MAE | Context SRC / MAE | Text + context SRC / MAE | Best SRC | Best MAE |
| ---: | ---: | --- | ---: | ---: | ---: | --- | --- |
| 15% | 6,410 | 2016-01-27 | 0.576 / 1.606 | 0.312 / 1.926 | 0.567 / 1.660 | TF-IDF | TF-IDF |
| 20% | 8,546 | 2016-01-11 | 0.575 / 1.623 | 0.317 / 1.898 | 0.578 / 1.642 | Text + context | TF-IDF |
| 25% | 10,683 | 2015-12-31 | 0.528 / 1.661 | 0.324 / 1.856 | 0.556 / 1.679 | Text + context | TF-IDF |

The holdouts are nested tails from the same seven-shard sample and overlap; they are sensitivity checks, not independent test sets. TF-IDF has the best MAE at all three windows, while SRC leadership changes at the 20% window. The ranking is therefore not fully stable across cutoffs. The chronological split currently uses a fixed random seed only for the separate user-group split; the temporal boundaries themselves are deterministic.

The complete report is `artifacts/baseline-metrics.json`. Models are stored under `artifacts/models/` and included with the research repository under the SMP Challenge Community License. Scores are not official test results and do not establish expected performance on the entire training split.

## Run and Reproduce

Create the cache and train the baselines:

```bash
HF_HUB_DOWNLOAD_TIMEOUT=120 .venv/bin/python -u -m viralscope.sample_cache --sample-shards 7 --workers 4
.venv/bin/python -u -m viralscope.train_baselines --workers 4
HF_HUB_DOWNLOAD_TIMEOUT=120 .venv/bin/python -u -m viralscope.user_aware_eval --workers 4
.venv/bin/python -u -m viralscope.temporal_sensitivity --workers 4
```

The cache and trained models are local artifacts; the commands do not download image bytes. Run tests with:

```bash
.venv/bin/python -m unittest discover -s tests -v
```

## Limitations and Next Checks

- Increase sample coverage only after the current pipeline is reproducible; do not jump to the full image-bearing Parquet download for these feature groups.
- Tune hyperparameters only on a separate validation split; do not select a final model by repeatedly consulting holdout windows.
- Design a combined future-time/unseen-user protocol if that is the intended deployment claim.
- Validate contribution explanations across representative examples and inspect them for text artifacts before any broader release.
- Generate and inspect residual/category plots for further cutoffs if they are used for model selection.
- Keep image training deferred until the supervisor reviews the license conditions for image use and display.
